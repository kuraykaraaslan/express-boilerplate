# fleet_protocol

Leaf contract package for the fleet federation (`docs/phases/02-fleet`). Pure functions and zod schemas: canonical JSON, Ed25519 signing and verification of the message envelope, sealed boxes for PII-capable fields, the closed command catalogue, policy merge, release verification, and protocol version negotiation. Infrastructure tier, requires only `common`.

It owns **no tables, no routes, no UI, no settings, no env vars, no extension points and no I/O** (only `node:crypto` and `zod`). It does **not** own key storage, the replay ledger, the control plane (`fleet`) or the node agent (`fleet_agent`); both of those require it. Rules 6-8 of the verification order (replay ledger, catalogue check, policy check) are left to the agent.

## Verification rules

`verifyEnvelope(raw, ctx)` applies, in order, and returns `{ ok: true, envelope }` or `{ ok: false, decision }`:

1. schema, plus a canonicalisation check (`REJECTED_SCHEMA`);
2. `aud` equals `ctx.self` (`REJECTED_AUD`);
3. `kid` known and not revoked (`REJECTED_KID`); a `cmd` must come from `iss: 'fleet'`, and a key's optional `issuers` list must contain `iss` (`REJECTED_ISSUER`);
4. signature (`REJECTED_SIGNATURE`);
5. time: `nbf` later than now plus skew (default 60 s) is `NOT_YET_VALID`; `exp <= now` is `EXPIRED`; `exp - iat` above `maxTtlSeconds` is `REJECTED_SCHEMA`.

`verifyRelease` checks, in order: version semver and channel format, manifest schema, digest pins (`REJECTED_DIGEST_PIN`, `REJECTED_DUPLICATE_TARGET`; image refs with shell or template metacharacters are refused), a non-revoked release-manager key (`REJECTED_SIGNER`), the signature over the canonical `(version, channel, manifest, ciProvenanceRef)` tuple, then the injected `verifyProvenance` port, which fails closed (`REJECTED_PROVENANCE`). It returns the signed version and channel so admission cannot use unsigned values. `checkReleaseAdmission` (node side) returns `REJECTED_CHANNEL`, `REJECTED_NOT_PINNED`, `REJECTED_AGENT_VERSION` (SemVer 2.0 precedence with BigInt cores; a pre-release sorts below its release; unparsable fails closed) or `REJECTED_PROTOCOL`, else `null`.

`verifySignedRelease(raw, { ciKeys, releaseManagerKeys, now, skewSeconds?, allowedSources? })` is the keys-in, no-port form of the same trust model (07 section 5.1, O-16 leaning: a CI-held provenance key plus the human signature). The CI attestation signs `(repo, ref, workflow, manifestHash, target -> digest pairs, builtAt, exp)`; the release manager signs `(version, channel, manifestHash, provenanceHash, signedAt, exp)`, where `provenanceHash` covers the whole attestation, so the human signs what they reviewed and the CI half cannot be swapped afterwards. Order: shape (a missing half is `REJECTED_NO_PROVENANCE` / `REJECTED_NO_APPROVAL`, never a pass), manifest schema (including the migration plan) and digest pins, CI kid (`REJECTED_PROVENANCE_KID`), release manager kid (`REJECTED_SIGNER`), one key in both roles (`REJECTED_SAME_KEY`), CI signature (`REJECTED_PROVENANCE`), human signature (`REJECTED_SIGNATURE`), bindings (manifest hash, exact digest set, attestation hash), then the optional source pin (`allowedSources`: attested `repo` and `workflow` must equal an entry, `ref` must start with its `refPrefix` when given, else `REJECTED_PROVENANCE`; omitted = not pinned), then time (`REJECTED_EXPIRED` when either `exp <= now`, `REJECTED_NOT_YET_VALID` when a signing time is more than the skew ahead; a lifetime above 90 days or an `exp` not after the signing time is `REJECTED_SCHEMA`). It returns the signed version, channel and manifest hash. The older flat `verifyRelease` (human signature plus an injected `verifyProvenance` port, for a cosign or Rekor lookup) stays for callers that verify provenance elsewhere.

## Command catalogue

Command classes run 0 to 3; what each class requires is defined in `docs/phases/02-fleet`, not here. Derived classes: `service.restart` is 2 for `caddy` else 1; `maintenance.open` is 2 for `SYSTEM`/`FULL` else 1; `policy.apply` is 3 when `loosens` else 1; `agent.update` is 2 once `coolingPeriodElapsed` else 3 (`isCoolingPeriodElapsed` derives it from the publish time). `release.deploy` carries a per-node `strategy` (`BLUE_GREEN` or `RECREATE`); rollout shapes belong to the plan. `release.deploy`, `release.rollback` and `agent.update` also carry a required `manifestHash` (64 lower-case hex, `ManifestHashSchema`; for the rollback it is the hash of `fromReleaseId`) that the control plane fills from the release row: the command signature binds the release id to its content (decision 19), and `fleet-deployd` refuses a release whose manifest hashes to anything else. Rough grouping: class 0 for `node.ping`, `node.inventory`, `node.time_sync`, `telemetry.snapshot`; class 3 for failover, secret rotation, tenant export/migrate/delete/purge/restore, break-glass grant, identity and user erase/dossier fan-out, node suspend/resume/decommission. The catalogue test compares the code against a doc table, so adding a kind means updating both.

## Dependencies

Requires `common` only. Required by `fleet`, `fleet_agent` and `license_client`.

## Tests

`server/tests/`: `fleet_protocol.crypto` (canonical JSON, sign/verify and rule order, key helpers, seal, version negotiation), `fleet_protocol.schemas` (policy merge per axis direction, denylist, G telemetry, migration contract, release manifest), `fleet_protocol.catalogue` (closure against the doc table, strict schemas, derived classes, G result), `fleet_protocol.release` and `fleet_protocol.release.review-2026-10-12` (signature binding, provenance, admission, pre-release and huge-number version semantics, ref injection), `fleet_protocol.release.signed` (CI-only and human-only refused, mutated fields, wrong key, unknown and revoked kid, expiry and skew, manifest rules under both signatures), `fleet_protocol.release.halves` (draft admission, publish-step approval binding, statement builder, SemVer compare), `fleet_protocol.trust-bundle.release` (optional slots, version skew, check, diff, keys into `verifySignedRelease`), `fleet_protocol.deployd.verbs` (closed verb set, no path or command carrying field, framing, kind-to-verb mapping against the doc table) and `fleet_protocol.migration-contract` (phase ordering, READ_ONLY window rule, rollback across contract).

## Known gaps

- `module.json` declares no `menu`, `routes`, `permissions` or `extensions`; the module is code only, by design.
- Envelope `body` is only `record<string, unknown>` here; typing per `typ` is done by `checkCommandBody` for `cmd` bodies, and no other `typ` has a schema in this package except `GResultSchema` and `GTelemetrySchema`, which callers must apply themselves.
- Replay protection (`jti` ledger), policy enforcement and key lifecycle are not in this package.
